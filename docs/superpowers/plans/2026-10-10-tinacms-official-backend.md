# TinaCMS Official Self-Hosted Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement TinaCMS self-hosted backend using official packages (@tinacms/datalayer, tinacms-gitprovider-github, tinacms-authjs) with SQLite database for content indexing.

**Architecture:** Official TinaCMS backend using TinaNodeBackend with SQLite database, GitHub OAuth authentication via NextAuth, and GitHub provider for git operations. Single-domain setup with admin UI at /admin.

**Tech Stack:**

- TinaCMS 3.14.0 (admin UI)
- @tinacms/datalayer 2.0.30 (backend runtime)
- tinacms-gitprovider-github 4.1.17 (git operations)
- tinacms-authjs 24.0.4 (authentication)
- better-sqlite3 (SQLite database)
- Astro 6 SSR with @astrojs/node adapter

**Spec:** `docs/superpowers/specs/tina-deploy-spec.md`

## Global Constraints

- Node.js >= 22.12.0
- Work only on code/project - no server, Virtualmin, Apache, DNS, SSL, systemd, or deployment changes
- Preserve existing equipment collection and bilingual fields structure
- Maintain compatibility with `bun run dev` and `bun run build`
- All credentials via environment variables
- GitHub repository: LilConsul/ocs.com.ua
- Single-domain architecture: dev.ocs.com.ua with /admin for TinaCMS
- Use SQLite for database (lightweight, file-based, no server process)

```typescript
import { createDatabase, createLocalDatabase } from "@tinacms/datalayer";
import { Level } from "level";
import path from "node:path";

const isProduction = process.env.NODE_ENV === "production";
const isDevelopment = !isProduction;

// Database path - use project root for persistence
const DB_PATH = path.join(process.cwd(), ".tina", "database");

/**
 * Create TinaCMS database client
 * Uses Level (LevelDB) for lightweight file-based storage
 */
export async function createDatabaseClient() {
	if (isDevelopment) {
		// Development: Use local database (faster, no persistence needed)
		console.log("[TinaCMS] Using local in-memory database");
		return createLocalDatabase();
	}

	// Production: Use persistent Level database
	console.log(`[TinaCMS] Using Level database at ${DB_PATH}`);

	const level = new Level(DB_PATH, {
		valueEncoding: "json",
	});

	return createDatabase({
		level,
		namespace: "tinacms",
	});
}
```

```typescript
import type { APIRoute } from "astro";
import { TinaNodeBackend, LocalBackendAuthProvider } from "@tinacms/datalayer";
import { GitHubProvider } from "tinacms-gitprovider-github";
import { AuthJsBackendAuthProvider, TinaAuthJSOptions } from "tinacms-authjs";
import { createDatabaseClient } from "../../../lib/tina/database";

// Environment variables
const GITHUB_OWNER = process.env.GITHUB_OWNER || "LilConsul";
const GITHUB_REPO = process.env.GITHUB_REPO || "ocs.com.ua";
const GITHUB_BRANCH = process.env.GITHUB_BRANCH || "main";
const GITHUB_TOKEN = process.env.GITHUB_PERSONAL_ACCESS_TOKEN || "";
const NEXTAUTH_SECRET = process.env.NEXTAUTH_SECRET || "";
const IS_LOCAL = process.env.TINA_PUBLIC_IS_LOCAL === "true";

if (!GITHUB_TOKEN && !IS_LOCAL) {
	console.warn("[TinaCMS] Missing GITHUB_PERSONAL_ACCESS_TOKEN");
}

if (!NEXTAUTH_SECRET && !IS_LOCAL) {
	console.warn("[TinaCMS] Missing NEXTAUTH_SECRET");
}

/**
 * Initialize TinaCMS backend
 * This is called once and cached
 */
let backendHandler: any = null;

async function getBackendHandler() {
	if (backendHandler) {
		return backendHandler;
	}

	console.log("[TinaCMS] Initializing backend handler...");

	// Create database client
	const databaseClient = await createDatabaseClient();

	// Create GitHub provider for git operations
	const gitProvider = new GitHubProvider({
		owner: GITHUB_OWNER,
		repo: GITHUB_REPO,
		token: GITHUB_TOKEN,
		branch: GITHUB_BRANCH,
	});

	// Create auth provider
	const authProvider = IS_LOCAL
		? LocalBackendAuthProvider()
		: AuthJsBackendAuthProvider({
				authOptions: TinaAuthJSOptions({
					databaseClient: databaseClient as any,
					secret: NEXTAUTH_SECRET,
				}),
		  });

	// Create TinaCMS backend
	backendHandler = TinaNodeBackend({
		authProvider,
		databaseClient: databaseClient as any,
		gitProvider,
	});

	console.log("[TinaCMS] Backend handler initialized");
	return backendHandler;
}

/**
 * Handle all HTTP methods for TinaCMS backend
 */
async function handleRequest(request: Request): Promise<Response> {
	try {
		const handler = await getBackendHandler();

		// Convert Astro Request to Node.js-compatible request
		const url = new URL(request.url);
		const body = request.method !== "GET" ? await request.text() : undefined;

		// Create Node.js-style request object
		const nodeReq: any = {
			method: request.method,
			url: url.pathname + url.search,
			headers: Object.fromEntries(request.headers.entries()),
			body: body ? JSON.parse(body) : undefined,
		};

		// Create Node.js-style response object
		let responseData: any = {};
		let statusCode = 200;

		const nodeRes: any = {
			statusCode: 200,
			setHeader: () => {},
			writeHead: (code: number) => {
				statusCode = code;
			},
			end: (data: string) => {
				responseData = data;
			},
		};

		// Call TinaNodeBackend handler
		await handler(nodeReq, nodeRes);

		// Convert back to Astro Response
		return new Response(responseData, {
			status: statusCode,
			headers: {
				"Content-Type": "application/json",
			},
		});
	} catch (error: any) {
		console.error("[TinaCMS] Backend error:", error);
		return new Response(
			JSON.stringify({
				error: error.message || "Internal server error",
			}),
			{
				status: 500,
				headers: {
					"Content-Type": "application/json",
				},
			},
		);
	}
}

// Export handlers for all HTTP methods
export const GET: APIRoute = async ({ request }) => handleRequest(request);
export const POST: APIRoute = async ({ request }) => handleRequest(request);
export const PUT: APIRoute = async ({ request }) => handleRequest(request);
export const DELETE: APIRoute = async ({ request }) => handleRequest(request);
export const PATCH: APIRoute = async ({ request }) => handleRequest(request);

export const prerender = false;
```

````
## Data Flow

### Read Operation (Query)

1. User opens equipment item in admin UI
2. Admin UI sends GraphQL query to `/api/tina`
3. TinaNodeBackend:
   - AuthJsBackendAuthProvider verifies session
   - Queries Level database for content
   - Returns formatted GraphQL response
4. Admin UI displays content

### Write Operation (Mutation)

1. User edits equipment item and clicks Save
2. Admin UI sends GraphQL mutation to `/api/tina`
3. TinaNodeBackend:
   - AuthJsBackendAuthProvider verifies session
   - Updates Level database
   - Calls GitHubProvider to commit changes
4. GitHubProvider:
   - Creates git commit with author metadata
   - Pushes to GitHub using Personal Access Token
5. Returns success to admin UI

## File Storage

**Content Files:**
- Location: `src/content/equipment/*.md`
- Format: Markdown with YAML frontmatter
- Source of truth: Git repository

**Database:**
- Location: `.tina/database/` (git-ignored)
- Purpose: Content indexing and fast queries
- Type: Level (LevelDB) with JSON encoding
- Ephemeral: Can be rebuilt from content files

**Generated Files:**
- `tina/__generated__/client.ts` - TinaCMS GraphQL client
- `tina/__generated__/databaseClient.ts` - Database client wrapper
- `public/admin/` - TinaCMS admin UI build

## Authentication Flow

1. User visits `/admin`
2. TinaCMS checks for session cookie
3. If no session, redirects to `/api/auth/signin`
4. NextAuth handles GitHub OAuth:
   - Redirects to GitHub
   - User authorizes app
   - GitHub redirects to `/api/auth/callback/github`
   - NextAuth creates JWT session
5. User redirected back to `/admin` with session
6. All mutations verify session via AuthJsBackendAuthProvider

## Environment Modes

**Development (`TINA_PUBLIC_IS_LOCAL=true`):**
- Uses LocalBackendAuthProvider (no auth)
- Uses in-memory database
- Git operations disabled
- Fast iteration

**Production (`TINA_PUBLIC_IS_LOCAL=false`):**
- Uses AuthJsBackendAuthProvider
- Uses persistent Level database
- Git operations push to GitHub
- Full authentication required

    "documents": ["item1.md", "item2.md", ...],
    "lastModified": "2024-10-10T..."
  }
}
````

**Document Cache:**

```json
{
  "equipment/item1.md": {
```

## Git Operations

**Commit Message Format:**

```
feat: update equipment via TinaCMS

Updated by: User Name <email@example.com>
File: src/content/equipment/item.md
```

**Author Attribution:**

- Name: From GitHub OAuth profile
- Email: From GitHub OAuth profile

**Branch:**

- Configured via `GITHUB_BRANCH` (default: main)
- Direct commits (no PR workflow)

## Security

**Authentication:**

- GitHub OAuth (industry standard)
- JWT sessions (secure, stateless)
- Optional: Restrict to organization/specific users

**Authorization:**

- Session verified on every mutation
- Read operations also require auth in production
- Local mode bypasses auth (localhost only)

**Git Access:**

- Personal Access Token with `repo` scope
- Stored as environment variable
- Never exposed to client

**Database:**

- Local file, no network access
- Not exposed via API
- Can only be accessed by backend process

## Troubleshooting

**Database Issues:**

- Delete `.tina/database/` to rebuild
- Check write permissions
- Verify Level package installed

**Git Issues:**

- Check GITHUB_PERSONAL_ACCESS_TOKEN
- Verify token has `repo` scope
- Check GitHub API rate limits

**Auth Issues:**

- Verify NEXTAUTH_SECRET is set
- Check OAuth callback URL matches
- Ensure NEXTAUTH_URL is correct

## Performance

**Database Size:**

- ~10-20 equipment items: \<1MB
- Database operations: \<10ms
- Rebuilds automatically if corrupted

**Git Operations:**

- Commit + push: 1-3 seconds
- Async (doesn't block UI)
- Failures logged, can retry manually

**Scaling:**

- Current setup: Good for \<100 content items
- For 100-1000 items: Consider Redis instead of Level
- For 1000+ items: Consider MongoDB with @tinacms/datalayer full setup
