# Decap CMS Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace TinaCMS with Decap CMS (formerly Netlify CMS) to enable web-based catalogue editing with GitHub OAuth authentication - no backend server or database required.

**Architecture:** Decap CMS runs entirely client-side in the browser, authenticates via GitHub OAuth, and commits changes directly to the GitHub repository. Zero infrastructure needed.

**Tech Stack:**

- Decap CMS 3.3.x (latest stable)
- GitHub OAuth (via GitHub settings)
- Astro 6 SSR (for serving the admin page)
- Existing equipment markdown files (no migration needed)

**Spec:** `docs/superpowers/specs/tina-deploy-spec.md` (same goal, different implementation)

## Global Constraints

- Node.js >= 22.12.0
- Work only on code/project - no server, Virtualmin, Apache, DNS, SSL, systemd, or deployment changes
- Preserve existing equipment collection and bilingual fields structure (no content migration needed)
- Maintain compatibility with `bun run dev` and `bun run build`
- All credentials via environment variables
- No MongoDB or external database dependencies
- GitHub repository: LilConsul/ocs.com.ua
- Single-domain architecture: dev.ocs.com.ua with /admin for Decap CMS

______________________________________________________________________

## Why Decap CMS Over TinaCMS

**From investigation findings:**

- TinaCMS self-hosted requires custom backend OR TinaCloud ($29/mo)
- Decap CMS has built-in GitHub OAuth (no backend needed)
- Both work with markdown files
- Decap is simpler for web-based editing with auth

**What we're removing:**

- All TinaCMS packages (@tinacms/astro, tinacms, @tinacms/cli)
- TinaCMS config and generated files
- Failed TinaCMS backend attempts

**What we're adding:**

- Decap CMS (~50KB)
- Config file for equipment collection
- Admin route serving Decap UI

- [ ] **Step 1: Create GitHub OAuth App**

1. Go to: https://github.com/settings/developers
1. Click "New OAuth App"
1. Fill in:
   - **Application name**: Decap CMS - OS-Technology
   - **Homepage URL**: https://dev.ocs.com.ua
   - **Authorization callback URL**: https://api.netlify.com/auth/done
   - **Description**: Content management for OS-Technology equipment catalogue
1. Click "Register application"
1. Note the **Client ID**
1. Click "Generate a new client secret" and note the **Client Secret**

**Important:** For Decap CMS with GitHub backend, you use Netlify's OAuth gateway (free service) even if not hosted on Netlify. The callback URL must be `https://api.netlify.com/auth/done`.

- [ ] **Step 2: Update config.yml with OAuth client ID**

Update `public/admin/config.yml` backend section:

```yaml
backend:
  name: github
  repo: LilConsul/ocs.com.ua
  branch: main
  auth_type: implicit
  # Client ID from GitHub OAuth app (not sensitive, can be public)
  client_id: <your_github_oauth_client_id>
```

Note: With Netlify's OAuth gateway, you don't need to handle client secret in your app.

# Decap CMS Setup Guide

## Overview

Decap CMS (formerly Netlify CMS) is a client-side content management system that:
- Runs entirely in the browser (no backend server)
- Authenticates via GitHub OAuth
- Commits changes directly to GitHub repository
- Requires zero infrastructure (no database, no API server)

## Architecture

\`\`\`
User → https://dev.ocs.com.ua/admin → Decap CMS (client-side)
                                           ↓
                                    GitHub OAuth Auth
                                           ↓
                                    GitHub API (commits)
                                           ↓
                                    LilConsul/ocs.com.ua repo
\`\`\`

## Local Development

### Prerequisites

- Bun runtime
- Git repository access
- GitHub OAuth App (for testing web-based auth)

### Steps

1. Install dependencies: `bun install`
2. Start dev server: `bun run dev`
3. Open http://localhost:4321/admin
4. Login with GitHub
5. Edit equipment collection

**Local dev behavior:**
- Changes write directly to local files
- No auto-commit (you commit manually)
- Perfect for testing content structure

## Production Deployment

### Prerequisites

- Static site hosting (any provider: Netlify, Vercel, Cloudflare Pages, or your server)
- GitHub OAuth App configured
- HTTPS domain (required for OAuth)

### GitHub OAuth Setup

1. Create production OAuth app:
   - Go to https://github.com/settings/developers
   - Click "New OAuth App"
   - **Homepage URL**: https://dev.ocs.com.ua
   - **Callback URL**: https://api.netlify.com/auth/done
   - Note Client ID

2. Update `public/admin/config.yml`:
   \`\`\`yaml
   backend:
     name: github
     repo: LilConsul/ocs.com.ua
     branch: main
     client_id: <your_production_client_id>
   \`\`\`

3. Commit and deploy

### Deployment Steps

1. Build site: `bun run build`
2. Deploy `dist/` to hosting
3. Visit https://dev.ocs.com.ua/admin
4. Login with GitHub
5. Edit content

**Production behavior:**
- Changes commit directly to GitHub
- Automatic deployment webhook triggers rebuild
- No local files, all changes in Git

## Content Structure

**Equipment Collection:**
- Location: `application/frontend/src/content/equipment/*.md`
- Format: Markdown with YAML frontmatter
- Fields: Bilingual (EN/UA), industries, gallery, specs

**Media Files:**
- Location: `application/frontend/public/assets/`
- Uploaded via Decap CMS media library
- Referenced in markdown by relative path

## Authentication

**Who can edit:**
- Anyone with GitHub account who authorizes the OAuth app
- By default: Any GitHub user

**Restrict access:**

Edit `public/admin/config.yml` to add:

\`\`\`yaml
backend:
  name: github
  repo: LilConsul/ocs.com.ua
  branch: main
  client_id: <client_id>
  # Restrict to organization members
  # base_url: https://your-custom-oauth-server.com
\`\`\`

To restrict to specific users/organization, you'd need a custom OAuth server. Most teams use:
- **GitHub organization** - Make repo private, only org members can access
- **Branch protection** - Require PR reviews for edits
- **Trust GitHub auth** - Anyone with GitHub account is acceptable

## Troubleshooting

### "Error: Failed to load config"

**Cause:** config.yml has syntax error or missing fields

**Fix:**
1. Validate YAML syntax
2. Check all required fields present
3. Check browser console for specific error

### "Error: Failed to authenticate"

**Cause:** OAuth app misconfigured or client ID wrong

**Fix:**
1. Verify callback URL: `https://api.netlify.com/auth/done`
2. Check client ID in config.yml matches GitHub app
3. Ensure OAuth app is active

### Media uploads fail

**Cause:** Media folder path incorrect

**Fix:**
1. Check `media_folder` in config.yml matches actual path
2. Ensure `public_folder` is correct for markdown references

### Changes don't appear on site

**Cause:** Site not rebuilding after Git commit

**Fix:**
1. Check deployment webhook configured
2. Verify GitHub Actions or hosting auto-deploy working
3. Manual deploy if needed

## Comparison: Decap CMS vs TinaCMS

| Feature | Decap CMS | TinaCMS Self-Hosted |
|---------|-----------|---------------------|
| Backend server | ❌ None | ✅ Required |
| Database | ❌ None | ✅ Required (or complex filesystem setup) |
| Authentication | ✅ GitHub OAuth built-in | ❌ Must build yourself |
| Infrastructure | Zero | High |
| Setup complexity | Low | High |
| Maintenance | Low | High |
| UI modernity | Good | Excellent |
| Git integration | ✅ Direct | Via backend |

**For small teams with Git-based workflow:** Decap CMS is simpler and more reliable.

**For non-technical users or advanced features:** TinaCloud (paid) is better than self-hosted TinaCMS.
