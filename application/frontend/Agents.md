## Project Overview

This is the frontend of OS-Technology Ukraine's B2B industrial weighing equipment website, in `application/frontend`. It is built with **Astro 7**, **Tailwind 4** and **Decap CMS**. It is bilingual (`/ua` default, `/en`) and optimized for SEO and LLM indexing.

The repository root also holds `application/infra` (Python/uv deploy tooling), `docs/info` (setup, environment and deployment guides), `.github` (CI and deploy) and a `Makefile`. Read the guides in `docs/info/` before changing environment variables, deployment or CI:

- `docs/info/development.md` - commands, i18n, content and CMS, git hooks, commit format
- `docs/info/environment.md` - every environment variable and feature flag
- `docs/info/deployment.md` - CI, dev deploy pipeline, server layout, GitHub secrets

**Key Requirements:**

- Language paths `/en` and `/ua`, every page exists in both languages
- Best-in-class SEO and LLM indexing (structured data, hreflang, sitemap)
- Maximum loading speed: public pages are prerendered static HTML
- Design from the Stitch design system (see `docs/design/`)
- Strict code quality with Biome

## Essential Commands

Run from `application/frontend` unless noted.

```bash
# Development
bun run dev              # Dev server at localhost:4321
bun run build            # Production build into ./dist/
bun run preview          # Preview the production build
bun test                 # Unit tests

# Code quality (ALWAYS RUN BEFORE COMMITS)
bun run check:fix        # Biome fix + Prettier on .astro/.tsx/.jsx
bun run check            # Biome check without fixing
bun run ci               # Biome CI mode (no fixes)

# i18n
bun run i18n             # Extract + compile in one step
bun run i18n:extract     # Extract _() calls to locales/*.po (keeps existing translations)
bun run i18n:compile     # Compile .po files to src/i18n/ui.ts
bun run i18n:init -- pl  # Create a PO file for a new language

# Content Markdown (src/content)
bun run remark:check
bun run remark:write

# Packages
bun install
bun add <package>
bun add -D <package>
```

From the repository root: `make install-dev` (deps and git hooks), `make env` (create or sync `.env.local`), `make test` (frontend and infra tests).

## Architecture & Key Patterns

### Routing and rendering

- Astro `output: "static"` with the Node adapter. **All public pages are prerendered.** Only three routes run on demand (`export const prerender = false`): `src/pages/api/auth.ts`, `src/pages/api/contact.ts` and `src/pages/admin/config.yml.ts`.
- A new on-demand route must also be proxied to Node in `application/infra/apache/dev.ocs.com.ua.ocs.conf`, otherwise it works only locally. Prefer prerendered pages.
- Localized pages live under `src/pages/[lang]/` and use `getStaticPaths()` to emit `/en` and `/ua`. `/` redirects to `/ua`.
- `i18n.routing` is `"manual"` (needed so the locale-less `/admin` renders); `src/middleware.ts` is a no-op required by that setting. Locale validation lives in the `[lang]` pages.
- Old `/{lang}/catalogue/{category}` URLs redirect to `/{lang}/catalogue/equipment/...`, generated by `scripts/catalogue-redirects.mjs`.

### i18n (Critical)

Use the **inline** pattern: write English text in the component and wrap it in `_()`.

```astro
---
import { getInlineTranslations, type Lang } from "@/i18n";

interface Props {
	lang: Lang;
}

const { lang } = Astro.props;
const _ = getInlineTranslations(lang);
---

<h1>{_("High-Speed Dynamic Weighing Systems")}</h1>
```

- DO call `_()` directly in the component that renders the text and pass `lang` as a prop.
- DON'T build translation dictionaries or pass translated strings down as props.
- `getTranslations()` (key lookup) still exists in `src/i18n/utils.ts` but no page or component uses it. Do not use it for new code.
- After adding `_()` calls run `bun run i18n`, then edit the `msgstr` values in `locales/ua.po` and run it again so they compile.

Files:

- `locales/messages.pot` - AUTO-GENERATED template, never edit
- `locales/ua.po` - EDIT the `msgstr` values here
- `src/i18n/ui.ts` - AUTO-GENERATED, never edit (header says so)
- `src/i18n/inline.ts` - `getInlineTranslations()`; `src/i18n/utils.ts` - `getLangFromUrl()`, `getIsoLang()`
- `scripts/i18n-extract-po.js`, `scripts/i18n-compile.js` - the tooling

Language codes are `ua` and `en`; the HTML `lang` attribute and hreflang use ISO `uk` through `getIsoLang()`.

### Components

- **Astro components** (`.astro`) are the default for layouts, pages and sections.
- Interactivity is a `<script>` tag inside the Astro component (see `Header.astro`, `CatalogueSidebar.astro`). Do not add UI frameworks, React islands or `client:*` directives. React is a dependency of Decap CMS only (`src/cms/`).
- Icons come from `@lucide/astro` (`import { ArrowRight } from "@lucide/astro"`, sized with `class`).
- Components are grouped by area: `homepage/`, `about/`, `catalogue/`, `contact/`, `wiki/`, `errors/`.
- `src/layouts/Layout.astro` wraps every page (SEO tags, hreflang, header, footer). The `<main>` has `pt-20` to clear the fixed header.

### Content and CMS

- Content collections are defined in `src/content.config.ts`: `equipment` (`src/content/equipment/<category>/<slug>.<lang>.md`) and `wiki` (`src/content/wiki/<slug>.<lang>.md`). Each article exists once per language.
- Structured data lives in `src/data/*.json` (equipment types, industries, partners, company, documents, icons).
- Helpers: `src/lib/content-utils.ts`, `src/lib/wiki-utils.ts`, `src/lib/catalogue-urls.ts`, `src/lib/structured-data.ts`.
- Decap CMS is bundled from `src/cms/` and served at `/admin`. Its config is generated by `/admin/config.yml` from `src/pages/admin/_config.template.yml`. When you add a content field, update both the schema in `content.config.ts` and the CMS template.
- Content Markdown is formatted by remark (`bun run remark:write`), not Prettier or mdformat.
- Images in `public/` must be real WebP/PNG/JPEG, at most 1600 px on a side and 300 KB. The pre-commit hook fixes them; `uv run application/infra/scripts/check-images.py` checks them.

### Environment variables and feature flags

- All configuration goes through typed `astro:env`: declare it in `astro.config.mjs`, import it with `import { NAME } from "astro:env/server"`.
- Feature flags (`SITE_DEV_NOTICE`, `SHOW_CLIENT_EQUIPMENT`) are public booleans, default `false`, inlined at build time.
- Adding a variable touches several places (schema, `.env.example`, deploy workflow, docs). Follow the checklist in `docs/info/environment.md`.
- Unit tests mock `astro:env/server` in `tests/helpers/mocks.ts`. If a module under test imports a new variable, add it there.

### Design System

- Fonts: headings `IBM Plex Sans Variable` (`--font-heading`), body `Inter Variable` (`--font-sans`), code and labels `JetBrains Mono`.
- Colors are CSS custom properties in `src/styles/global.css` in `oklch()`, with light and dark (`.dark`) values. Primary and secondary are pink-magenta; check the file for the exact tokens instead of hardcoding hex values.
- Tailwind 4 with `@theme inline` tokens.
- Aesthetic: Corporate Modern, minimalist, white space first, glassmorphism accents. Match it in new components and verify layouts in both languages (Ukrainian text is longer).

## Code Quality Rules

Biome (`biome.json`) and Prettier (`.prettierrc`, for `.astro`) must agree:

- Tabs (width 2), 100-character lines, double quotes, semicolons, ES5 trailing commas
- Unused imports and variables are OFF for Astro files (frontmatter quirk)
- `noExplicitAny` is a warning, off in tests
- Tailwind classes are sorted by `prettier-plugin-tailwindcss`

Run `bun run check:fix` before every commit. Pre-commit hooks (installed by `make install-dev`) also run i18n extraction, remark, image optimization and, on push, `biome ci`. A hook that modifies files fails the commit: re-stage and commit again.

Commit messages follow `.gitmessage`: `type(scope): subject`, imperative, lowercase, no period, at most 72 characters.

## SEO & Performance

- Use semantic HTML5 and a unique translated `title` and `description` per page through `Layout.astro`.
- Keep pages prerendered; avoid client-side JavaScript unless a feature needs it.
- Optimize images and size them explicitly.
- Add JSON-LD where appropriate (`src/lib/structured-data.ts`), keep a clear heading hierarchy, and use descriptive link text.

## Common Workflows

### Creating a New Bilingual Page

1. Create `src/pages/[lang]/page-name.astro`.
1. Export `getStaticPaths()` returning params for `en` and `ua`.
1. Wrap the page in `Layout.astro` and get `_` from `getInlineTranslations(lang)`.
1. Run `bun run i18n`, translate the new strings in `locales/ua.po`, run it again.
1. Add the link to the header or footer if needed.

### Working with Stitch Designs

1. Check alignment with the existing theme and tokens in `global.css`.
1. Reuse existing components where possible.
1. Keep accessibility standards and verify both languages.
